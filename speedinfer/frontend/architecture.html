CONTROL PLANE / DATA PLANE

Clear responsibility at each layer.

Control Plane — SpeedInfer

The gateway process owns the public API and coordination logic.

  • API authentication and scoped keys
  • RPM and TPM rate limits
  • Model registry and compatible-worker routing
  • Worker health and circuit-breaker state
  • Request forwarding and supported streaming
  • Usage reservations, settlement, and reporting

Data Plane — Connected workers

Workers load models and execute inference outside the gateway.

  • OpenAI-compatible workers
  • NVIDIA GPU workers
  • Triton HTTP v2 model endpoints
  • TensorRT-LLM through Triton or a compatible frontend
  • CUDA and GPU metadata reported through worker configuration

IMPLEMENTATION CONTRACT

What the gateway records and checks.

Worker registration

Each configured worker has an ID, worker type, runtime, runtime endpoint, supported models, runtime configuration, health state, and optional GPU/CUDA metadata.

Compatible routing

The registry filters unhealthy workers and workers that do not declare the requested public or base model. If none remain, the API returns a clear 503 response and releases the billing reservation.
