RESPONSIBILITY SPLIT

Control and execution stay separate.

SpeedInfer

Control plane, authentication, routing, usage, and developer API.

  • Scoped API authentication
  • Rate limits and credit reservations
  • Model registry and compatible-worker selection
  • Worker circuit state and health reporting
  • OpenAI-compatible requests and supported SSE forwarding
  • Authoritative usage settlement

NVIDIA stack

GPU-accelerated model execution and serving.

  • CUDA execution on the worker host
  • Triton server and model readiness
  • Triton HTTP v2 inference
  • TensorRT-LLM through Triton or a compatible API frontend
  • Worker-supplied GPU and runtime metadata
IMPLEMENTED INTEGRATION

Runtime behavior behind the diagram.

Registration

Server-side JSON defines the worker ID, runtime, endpoint, supported models, protocol settings, and metadata.

Discovery & health

Triton workers use server readiness, model readiness, and the ready-model repository index.

Inference

Direct Triton workers receive HTTP v2 tensor requests. OpenAI-compatible workers use the existing chat/completions proxy.

Streaming

SSE is forwarded from OpenAI-compatible TensorRT-LLM frontends. Direct Triton HTTP v2 returns a clear unsupported-streaming error.

Usage

Triton models must return configured prompt and completion token outputs. Unmetered responses fail and release the reservation.

Availability

Only healthy workers declaring the requested model are eligible. Otherwise SpeedInfer returns HTTP 503 without charging.
